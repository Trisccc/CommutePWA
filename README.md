# Commute Predictor — 分段通勤记录

第一城 ↔ HKUST 的个人通勤 PWA。纯 HTML / CSS / JavaScript，无后端，无账号。

## 使用流程

1. 选择「去 HKUST」或「回第一城」，然后选择具体路线。
2. 查看按顺序排列的分段，点击「开始所选路线」，立即开始第一段步行计时。
3. 到站点「下一段」开始等车；上车再点一次，开始乘车计时。换乘、等待和乘车分别记录。
4. 最后一段点「完成行程，查看总结」，核对各段时间并保存。
5. 误点可「撤销上次切换」，会把刚才的时间重新合并回上一段。中止的行程留在历史中，不用于学习。
6. 测试或忘记切换的记录，请勾选「测试 / 计时不准」。它会保存但不影响 ETA。

屏幕显示当前段、当前段用时、总用时、下一段及进度。计时使用时间戳差，刷新、锁屏后继续；网页不会在后台自动识别上车，请在实际转换时手动点击。开始后路线固定，不能在途中换成另一条路线。

## 路线和兼容性

保留既有校巴、91、91M、11 小巴路线。回程原本混合的 91 / 91M 拆为两条，旧路线历史保留。彩虹地铁行程进一步拆分钻石山换乘、等待观塘线及乘车段。10:15 九龙塘校巴仍是默认关闭的个人规则，在设置里启用，不能视为已核实的官方班次。

保留 GPS 方向判断、Home / HKUST 位置设置、实时交通面板、手动补记、历史和 JSON 导出。正在分段记录时不允许 GPS 改变本次方向。原来的总时长记录不伪造为分段数据，仍可在历史中查看。

现有交通实时面板仍显示当前站点 ETA。新的整条路线 ETA 使用个人分段预测之和；不会把「当前站点还有几分钟来车」直接当作几十分钟后抵达站点的候车时间。校巴时刻仅保留原有推荐规则；本版不是实时换乘时刻规划器，出发前仍应核对班次。新增换乘和拆分时间属于初始估计，需实测校准。

## 数据模型

主记录保存在 localStorage 的 commute_segment_state_v3，包含：

- version: 3；revision：每次保存递增，用于发现其他标签页的较新修改。
- trips：完整历史，包括迁移的旧记录和新的分段行程。
- active：当前行程或 null。状态 recording → review → completed；review 状态等待用户保存，不计入学习。
- distances：按分段 ID 保存用户填写的步行距离，单位米。

每条新行程保存 schemaVersion、id、routeId、routeName、direction、startedAt、endedAt、timestamp（出发时刻）、duration（总分钟）、predictedMinutes（出发时预测）、status、note、excludeLearning 和 segments。

每个 segment 保存 id、type、service、from、to、label、baselineMinutes、predictedMinutes、distanceMeters、startedAt、endedAt、durationMs。

分段 ID 为 type|service|from|to。例如 bus|91M|钻石山|HKUST 北站 与 bus|91M|彩虹|HKUST 北站 是两个模型；同一第一城→钻石山地铁段可以被多条路线共享。等车使用单独的 wait 类型，线路和站点也是标识的一部分。

active 另存 plan 快照和 segmentStartedAt。每次切换一次性保存当前段终点和下一段起点，因此完成行程的分段毫秒数之和等于整趟毫秒数。最终保存历史和清除 active 在同一个 localStorage 写入中完成，减少重复保存风险。保存失败会提示，不推进内存状态。多个标签页会同步更新；revision 检查不是数据库级事务，建议只在一个页面操作计时。

首次升级复制 commute_trips_v2 和 commute_active_trip_v1。旧键保留作为升级前备份；升级后 v3 是权威记录，旧版本网页不应继续用于记录。位置偏好继续使用 commute_settings_v2。

## 学习公式

统计由有效历史按出发顺序重建，删除记录后重新计算，不会留下该记录的模型影响。只使用 schemaVersion=3、status=completed 且 excludeLearning=false 的记录。

每段保存统计次数 n、EWMA 均值、最短及最长时间。另汇总类型（walk、wait、mtr、bus、minibus、shuttle、transfer），以及类型/线路/方向/起终点。类型均值用于展示，不直接拿不同长度的巴士段互相预测。

第一条记录初始化均值；之后：

    新均值 = 0.76 × 旧均值 + 0.24 × 本次分钟数

情境使用香港时区，区分工作日/周末与每两小时一个时间桶，按该段开始时刻归类。某情境至少有 3 条记录时：

    个人值 = 0.68 × 同情境均值 + 0.32 × 该段总体均值

否则使用该段总体均值。个人数据权重：

    w = min(0.9, n / (n + 5))
    分段预测 = (1 - w) × 初始值 + w × 个人值
    路线 ETA = 所有分段预测之和

预测逐段推进预计开始时刻，再选择该段的情境桶。偏好分只影响路线排序，不加到物理用时里。不显示未经校准的概率/信心百分比。

## 步速

在选好路线后展开「步行距离」，可填写已知距离；留空仍能学习这一段的耗时，但不能推导真实速度。不使用两点直线距离冒充实际步行路程。

有效步行段的配速 = 分钟 / 公里。只把 3–60 分/公里范围内的样本纳入通用步速 EWMA；这是数据合理性过滤，不修改原始记录。速度 km/h = 60 / 配速。

对已填距离的步行段，先用 min(0.7, 步速样本数/(样本数+5)) 将「配速×距离」与原始分钟值混合，再按上述分段公式混合该段历史。换乘段有自己的耗时统计，不混入纯步行速度。

## 本地数据与 PWA

数据只在当前浏览器/设备，不会自动跨设备同步。清理浏览器网站数据会清掉记录，建议使用设置中的 JSON 导出；导出包含历史、当前行程、距离、位置设置和重建统计。目前没有 JSON 导入界面。

GitHub Pages 提供 HTTPS 后，iPhone Safari 可「分享 → 添加到主屏幕」。PWA 在线优先取新文件，离线使用缓存，版本查询参数也能匹配离线脚本。实时交通在线不可用时显示缺省提示，分段计时仍可使用。

代码集中在 app.js，分段 v3 扩展替换原有计时、历史和推荐入口；sw.js 管理缓存。
